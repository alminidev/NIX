# CREATIVE PRINCIPLES — Sistema de Referências

## OBJETIVO

Referências existem para alimentar o processo criativo. Elas NÃO existem para serem copiadas.

A pergunta errada: "Como fazemos nosso projeto parecido com este?"
A pergunta certa: "O que este projeto faz excepcionalmente bem, e como aplicamos esse princípio de forma original?"

## O fluxo obrigatório

```
REFERENCE → OBSERVE → DECOMPOSE → EXTRACT PRINCIPLE → ABSTRACT → ADAPT → COMBINE → CREATE
```

Nunca: `REFERENCE → COPY`.

## Para cada referência, responda 5 perguntas

1. O que funciona?
2. Por que funciona?
3. Qual princípio pode ser extraído?
4. O que NÃO deve ser copiado?
5. Como adaptar o princípio ao projeto atual?

## Não dependa de uma única referência

Distribua os papéis:

| Referência | Extrair |
|---|---|
| A — site principal | personalidade, ritmo, hierarquia, navegação |
| B — segundo site | estrutura, storytelling, uso de espaço |
| C — tipografia | família, contraste, escala, peso, combinação serif/sans |
| D — composição | grid, assimetria, proporção, whitespace |
| E — motion | transições, hover, scroll behavior |
| F — opcional | fotografia, branding, interação |

O resultado final deve ser uma síntese original — não uma colagem reconhecível das partes.

## Regra de ouro

Nunca interprete "faça como o site X" como "clone o site X".

Interprete como: "identifique o que torna X excelente e traduza esses princípios para este projeto."

O resultado deve ser reconhecível como uma nova criação. O agente deve sempre conseguir explicar: "Estamos usando esta referência pela lógica de composição/tipografia/motion, não pela aparência."

## Saída esperada: CREATIVE DNA

Depois de analisar as referências, produza uma síntese assim:

```
# CREATIVE DNA

## PERSONALIDADE
(3-5 adjetivos que definem a personalidade do projeto)

## TIPOGRAFIA
(o princípio extraído, não a fonte copiada)

## COMPOSIÇÃO
(grid, proporção, uso de espaço)

## IMAGEM
(tratamento, estilo, crop)

## MOTION
(tipo de movimento, ritmo)

## NAVEGAÇÃO
(comportamento, densidade)

## NÃO USAR
(o que ficaria genérico ou clichê para este projeto específico)
```

Isso vira a constituição visual do projeto — todo o resto (art direction, design system, build) deve estar de acordo com ela.
